## 1. Systems, data, method

* **SFT-final** = `<HF_ORG>/gemma3-270m-translate` tag `step-27638`. **RL-final** = `<HF_ORG_LEGACY>/gemma-3-270m-translate-rl2c` `latest` (GRPO step 1433, `runs/final_1433`; the Hub sha used by the decoding study is `80baefff3b16`). Both: greedy, prompt `Translate the text to {language}:  {english}`, the language tag written by the model is stripped before scoring, metrics on NFC text, `max_new_tokens` 768 (the headline; section 6 gives FLORES+ at the 320 budget of the 2026-10-18/19 reports).
* **Pipeline**: the repo's `gemma_mt.eval.sft_benchmarks` through `scripts/eval_sft_benchmarks.sh` (vLLM worker, HF fallback), no AfriCOMET, no base model. Benchmarks: FLORES+ devtest (1,012 sentences, 45 languages), NTREX-128 (1,997, 24), MAFAND-MT test (15), SmolSent (863, 45), IbomMT (2), FLORES-MOZ (1), SALT (5), GlotStoryBook (8). Test splits only. GATITOS (words) and SmolDoc (documents) are not part of this table.
* **Metrics**: chrF++ (sacrebleu `word_order=2`), **spBLEU** = sacrebleu BLEU with `tokenize="flores200"` (no 13a BLEU is reported: it is not meaningful for these scripts), corpus-level per language and subset; macro = unweighted mean over the languages of the row set; `finished` = the completion ends with the stop token inside the budget; `LID` = GlotLID v3 top-1 label of the hypothesis is one of the language's labels (`LID~` also accepts sibling labels such as `swc` for `swh`).
* **Subsets** (contamination flags in `bench/test_sets/_contamination`): `all` = every row; `no_pair` = rows whose *reference pair* was not in the SFT text (the model never saw this translation; headline); `clean` = rows whose *English sentence* is not in the SFT text (for FLORES+ only 48 of 1,012 sentences, for SmolSent 76 of 863, so per-language clean numbers are noisy). The model has seen 95% of the FLORES+ English sentences in other language pairs, which is why `clean` is lower than `all`.
* **Groups** (from `languages.py`): `qe_validated` 42 languages (AfriCOMET-QE validated against human references), `blend` 12 (named on the AfriCOMET card, QE blended with the consensus signal), `consensus_only` 23 (no QE call, consensus reward only), `sft_only` 8 (SFT targets that were not RL-trained: nde fat knc gaa men luy tzm ful; per `languages.py` `nde`, `knc`, `ful`, `gaa` have no SFT data at all, so `nde` and `knc` rows are zero-shot and the model does not write their tag, `prefix_ok` = 0 and the tag stays in the scored text). The 77 RL languages are the first three groups.
* **Cross-check against the existing reports**: the new SFT-final numbers reproduce the 2026-10-19 rare-language report (same checkpoint, step 27638, 320 tokens, HF sampler there vs vLLM here) with a mean absolute difference of 0.1 chrF++ on IbomMT / FLORES-MOZ / GlotStoryBook / SALT / the 9 gain languages (largest +-0.9); the 2026-10-18 FLORES+ table is for the older step-20500 checkpoint, so the SFT side is regenerated here (all benchmarks, same pipeline as the RL side) instead of copied.

## 6. Effect of the token budget: FLORES+ at 320 vs 768 new tokens

The 2026-10-18/19 reports used 320 new tokens; this report's headline uses 768. A looping completion is scored as it stands, so the larger budget lets the looping SFT model append more repeated text (precision falls: SFT-final 30.6 at 320 -> 28.9 at 768 chrF++), while the RL model finishes every sentence inside either budget (34.3 at both). The RL-minus-SFT gain is therefore **+3.7 chrF++ at the 320 budget of the older reports and +5.4 at 768**; about 1.7 points of the 768 gain are the SFT model's runaway tail, the remaining +3.7 still contains the 10% of SFT sentences that loop inside 320 tokens. ## 8. Caveats

* **Non-comparable rows.** `shi` (Tachelhit) on NTREX has an Arabic-script reference while the model writes Latin transliteration: chrF++ 0.3 -> 1.0 is a script mismatch, not a quality measure (it is still inside the primary-benchmark macros of section 2.3; drop it for a clean average). `knc` and `nde` are zero-shot (no SFT data, see section 1). GlotLID right-language rates are not meaningful for `knc`, `nde` (0-3%), `kon` (no label) and are low for Pidgin / Nuer-like cases where GlotLID has no good class; compare SFT vs RL, not absolute values.
* FLORES+ `clean` rests on 48 sentences per language; per-language `clean` deltas are noisy (bootstrap CIs in the wide CSV), the macro is stable.
* All benchmarks are test splits that are never trained on, but the English side of 95% of FLORES+ devtest (91% of SmolSent) appears in the SFT text through other language pairs; `no_pair` removes only the rows whose own reference was seen, `clean` removes every row whose English sentence was seen. This audit covers the SFT text; the RL prompt pools were not re-audited against these test sets here.
* Macro averages weight a 48-sentence language like a 1,012-sentence one; the bootstrap resamples sentences within each language and averages languages with equal weight, i.e. it measures sentence-sampling noise, not language-sampling noise.
* Different benchmarks are not comparable with each other (different domains, lengths, reference quality); never read a difference between two benchmark columns as a difference between languages.

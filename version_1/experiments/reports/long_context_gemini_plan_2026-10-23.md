# Gemini Batch as a second pseudo-reference for the long-document benchmark: cost, scripts, plan (2026-10-23)

Agent LC1 helper deliverable. Nothing here called a paid API (no key available). All dollar figures below are generated by
`paper/scripts/gemini_batch_cost.py` from box-side counts + the prices JSON; re-run it to regenerate them. Items marked **[UNVERIFIED]** could not be
confirmed from an official page today.

## 0. Summary

* The whole benchmark is tiny in token terms (2,280 items = 2.68 M English source tokens by the chars/4 estimate, 2.27 M by the Gemma-3 count). Even the
  most expensive Gemini model costs well under $100 for the FULL set in Batch mode; the cheapest sensible option (2.5 Flash, thinking off, whole-document
  requests, Batch, output multiplier 2.75) costs **$9.636** for the FULL set and **$1.184** for the REDUCED set (270 items). 2.5 Flash-Lite would be $1.616 for
  the FULL set, but see the quality caveat: **nobody has measured Flash-Lite on these languages; the only African-language evidence in the repo is for 2.5 Flash.**
* Money is not the constraint, quality is. Gemini's quality in low-resource African languages is uneven (the owner's Urhobo silver set generated with Gemini was of
  doubtful quality). Use Gemini only for languages where the pilot (section 5) shows it beats the NLLB-3.3B pseudo-reference against human references.
* The cost driver is **thinking tokens** (billed as output, per request) and **request count**: chunked sentence-by-sentence requests with default thinking
  are ~18-30x more expensive than whole-document requests (chunk-8 with default thinking ~3x); with thinking off, chunking costs only +1..35 % (section 3).

### Thinking behaviour
* Thinking tokens are billed at the output price, even though only summaries are returned (thinking page), and they count toward `max_output_tokens` (set the cap with headroom).
* Today's thinking page documents control through `thinking_level` (`minimal|low|medium|high`, `generation_config.thinking_config`), with defaults: 2.5 Pro on, 2.5 Flash on, 2.5 Flash-Lite **off**,
  3.5 Flash-Lite on (minimal), 3.6 Flash on (medium), 3.8 Flash on (medium; lowest level low), 3.1 Pro on (high), Gemini 4 on (medium).
* The older 2.5-era `thinking_budget` (0 = off for Flash and Flash-Lite, -1 = dynamic, 2.5 Pro cannot be switched off with a minimum budget) is **not mentioned on today's page**; the generator
  supports both (`--thinking-budget N` / `--thinking-level X`) but whether 2.5 Flash still accepts `thinking_budget: 0` in Batch is **[UNVERIFIED]** -- test with the pilot (check `thoughtsTokenCount` = 0 in the results).
* Cost model: a separate line per scenario of hidden output tokens per request: **off +0**, **low +500**, **default +2000** (+200 for 3.5 Flash-Lite "minimal"; 0 for 2.5 Flash-Lite). The +500/+2000 values are
  assumptions, not measurements; `gemini_batch_ingest.py` reports the real `thoughtsTokenCount` share from the first batch.

## 2. Assumptions

1. English source tokens: Gemini's tokenizer cannot be called offline. The script default uses **chars/4** (Google's rule of thumb, conservative: 1.18x the Gemma-3 token count of the same text); `--src-basis gemma` uses the Gemma count.
2. **Output tokens = multiplier x English source tokens**, multiplier 2.0 (low) / 2.75 (mid) / 3.5 (high) for African-language output in the Gemini tokenizer. Not measured. **Amharic (Ge'ez script) may be higher than 3.5**; if
   Amharic comes out at ~5x, the Amharic share of the output (1/12 of core, 1/6 of sci) adds roughly 4-7 % to the high-case totals; check `candidatesTokenCount` in the first batch.
3. Instruction: system instruction of ~74 tokens (whole-document) / ~98 tokens (chunked), measured with the Gemma tokenizer, +10 framing tokens per request. This is *shorter* than the 120-200 tokens the brief suggested;
   with 200-token instructions the whole-document totals rise by <1 % and chunk-1 totals by roughly 15-30 %. Exact text: `INSTR_WHOLE` / `INSTR_CHUNK` in `paper/scripts/gemini_batch_common.py`.
4. Items = document x language. "Per 1,000 documents" in the CSV is dollars per 1,000 **items**.
5. No retries, no cached-content discount (implicit caching may reduce the repeated instruction; ignored), no failed-request refunds.
6. Reduced set = 8 languages (hau swh ibo mlg zul xho kin som; the ones Gemini beats NLLB by >= 3 chrF++ on, section 4) x 5 documents per bin (fixed seed 20261023) x 3 bins (b512, b1024, b2048) = 120 items,
   plus sci dev (25 papers x 6 languages = 150 items) as a separate row; "REDUCED total" = both (270 items).
7. FULL set = every item in `items.jsonl` (core b256-b4096 x 12 languages, human sm/st512/st1024/st2048 x 12, sci dev + test x 6) = 2,280 items from 290 documents.

## 4. Which languages to trust Gemini on

**Caveat (read first): Gemini's quality in low-resource African languages is uneven. The owner's Urhobo silver set generated by Gemini was of doubtful quality. Everything below is a screening step, not a licence to skip the pilot.**

Evidence available in the repo: `reports/data/published_baselines.csv` rows `Gemini-2.5-Flash` (42 languages; source arXiv 2507.16809) are chrF++ on **only the first 10 sentences of FLORES-200 dev+devtest (n=10, flag `low_n`)**, en->xx, with the
number of non-empty outputs recorded per language. With n=10 the standard error of a chrF++ mean is of the order of 5-8 points, so differences of a few points are noise. The NLLB-3.3B comparison numbers are (a) our own re-score
of NLLB-3.3B (CT2 int8, beam 4) on all 1,012 FLORES+ devtest sentences (`reports/data/model_comparison_master.csv`, subset all) and (b) the NLLB paper's own number (`published_baselines.csv`). **The Gemini and NLLB numbers therefore come from different
pipelines and different sentence subsets** (n=10 vs n=1012); the FLORES-200 vs FLORES+ revision difference is small but real. Only Gemini-**2.5-Flash** was measured; Flash-Lite, Pro and the 3.x/4 models have no number here.

Rule: use Gemini as a pseudo-reference for a language only if its FLORES chrF++ is >= NLLB-3.3B on both NLLB references (TRUST). MARGINAL = below on one or both references but by < 3 points (n=10 noise); NOT trusted until the pilot passes.

### Validation plan: 50-sentence pilot (do this before any larger spend)

1. **Sentences.** Two small sets, both with human references, same 50 English sentences for all languages within a source: (A) 50 sentences sampled with a fixed seed from FLORES+ devtest (reference = the FLORES+ human translation in each of the 14 languages incl. lug, nso, amh; supply them with `--pilot-file flores_pilot.jsonl`, rows `{id,text}`);
   (B) 50 sentences from the SmolDoc `sm` documents for the 12 human-benchmark languages (`gemini_batch_requests.py --pilot 50`, human references already in `refs_human.jsonl`), which matches the benchmark domain. Use (A) for the trust decision (all 14 languages) and (B) as a domain check.
2. **Systems.** Gemini candidate model(s) (e.g. 2.5 Flash thinking-off and the strongest model you may use, section 6), and NLLB-3.3B on the same 50 sentences (already available from our NLLB pipeline).
3. **Compute per language:** chrF++ (sacrebleu, word_order=2, same signature as `reports/data/model_comparison_master.csv`) of Gemini vs human ref and NLLB vs human ref; paired bootstrap (1000 resamples over the 50 sentences) for Gemini minus NLLB; blocked/empty/truncated rate; line-count mismatch rate (chunk mode); target-language ID / script check on the output (fraction detected as the right language, expect >= 95 %); length ratio hypothesis/reference.
4. **Pass rule (per language):** Gemini chrF++ >= NLLB chrF++ on the pilot **and** the 90 % one-sided paired-bootstrap lower bound of the difference > -3 chrF++, **and** blocked+empty+truncated <= 2 %, **and** wrong-language/script outputs <= 5 %, **and** length ratio within 0.7-1.5. Languages that fail are dropped from the Gemini pseudo-reference run (NLLB stays the only pseudo-reference there). With n=50 the test only detects gross differences; treat it as a gate against bad languages, not a ranking.
5. **Cost:** see table 3.3: the whole pilot is a few cents to a few dollars depending on model/thinking. Also read `usage` from the pilot results to replace the assumed multipliers and thinking overhead in `gemini_prices_2026-10-23.json` / the cost script before the big run.

## 5. Recommended options

1. **Pilot first** (section 4): 50 sentences x 14 languages with 2.5 Flash thinking-off Batch, and the same with one stronger model (3.8 Flash low or 2.5 Pro). Tens of cents to a few dollars (table 3.3).
2. **Reduced set, whole-document, Batch, thinking off/low** with the best-passing Flash-class model: core 120 items + sci dev 150 items. 2.5 Flash thinking-off costs $1.184 (mid multiplier) for both; 3.8 Flash low thinking costs roughly 1.8x that (table 3.1). Use `--selection reduced`.
3. **FULL set, whole-document, Batch** only if the reduced set shows Gemini agrees with the human references and the omission rate is low: 2.5 Flash thinking-off $9.636; 3.8 Flash low thinking and Pro-class models stay under ~$100 (table 3.1). Restrict `--langs` to the languages that passed.
4. Flash-Lite (2.5: $1.616 for the FULL set) is 6x cheaper than 2.5 Flash, but there is no FLORES evidence for it on these languages; run it through the same pilot before trusting it. Money saved is a few dollars, so default to a Flash-class (or better) model.
5. Do **not** use default thinking with chunk-1 on anything above Flash-Lite: it multiplies cost by ~18-30x for no demonstrated benefit on translation (table 3.2).
6. b4096 documents (10 docs x 12 languages) are the riskiest for omissions and for the output cap (~15-20 k output tokens). Run them last, and compare paragraph counts and length ratio against the NLLB pseudo-reference.

## 6. What can go wrong

* **Safety blocks / empty candidates.** News (GlobalVoices) and health text can trigger `promptFeedback.blockReason` or finishReason SAFETY/PROHIBITED_CONTENT. The ingest script records `status=blocked`; drop these items or re-run them chunked (blocks are often one sentence).
* **Truncation.** `finishReason=MAX_TOKENS` (status `truncated`); the cap is per request = min(65,536 [UNVERIFIED limit], 4.5 x source tokens + thinking headroom + 256), and thinking tokens count toward it. Never use truncated outputs as references.
* **Silent omission / summarisation** in whole-document mode is not detected by finishReason. Check paragraph count (blank-line blocks) and length ratio vs the English source and vs the NLLB pseudo-reference; flag items outside 0.6-1.6 of the median ratio.
* **Thinking tokens are billed as output** and reported as `thoughtsTokenCount`; on 2.5 Pro and Gemini 4 they cannot be turned off, on 3.8 Flash the minimum is `low`. Real overhead may exceed the assumed +2000/request.
* **Batch discount applies only to Batch** jobs (24 h SLA, may take up to 48 h before expiry); the interactive API costs 2x.
* **Rate/size limits:** enqueued-token cap per model and tier (Tier 1 Flash = 3 M tokens; whether the cap counts input only or input+output is UNVERIFIED; the FULL set is ~2.9 M estimated input tokens, so split); 100 concurrent batch requests; 2 GB per file (our FULL whole-document file is ~12 MB). Job creation is not idempotent.
* **Prices change:** 3.6/3.8 Flash and Gemini 4 Argon introductory prices end 2026-11-30 / 2026-12-31; 2.5 models are gated to existing users [see section 1]; model IDs of the 3.x family were taken from the pricing/thinking pages (3.1 Flash-Lite's ID **[UNVERIFIED]**).
* **Terms of use [read carefully, not legal advice]:** the Gemini API terms page says (paid services) prompts/responses are not used to improve Google's products, and forbids using the Services "to develop models that compete with the Services". It does not mention benchmark references, evaluation use or SynthID/watermarking (nothing found; **UNVERIFIED** whether outputs carry any watermark).
  Using Gemini outputs purely as *evaluation references* is the lower-risk reading; using them as *training data or RL reward targets* for SabiYarn/Gemma-MT is plausibly the "develop models" case. Decide with that in mind before feeding `pseudo_gemini.jsonl` into any training or RL stage.
* **Pseudo-reference bias:** Gemini-as-reference will favour systems that translate like Gemini; keep NLLB and the human references (SmolDoc/AfriScience) in the analysis and report agreement between pseudo-references.

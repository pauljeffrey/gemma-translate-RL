# Proposal: how much human data does RL need for very-low-resource languages? (draft 2026-10-24)

Owner idea (2026-10-24): RL improved several very-low-resource languages by many chrF++ points although AfriCOMET does not support them (we substituted consensus and rule-based rewards); would 1-4k human translations per language (ish, bin, bbj, kea, tiv) plus a metric adapted to them help more; and how far can a very small model go across many languages at a cost African researchers can afford?

## What our results already say (all from files)
- RL gains on FLORES+ `no_pair`, SFT-final -> RL-final (chrF++): kea 12.2 -> 26.8 (+14.6), kbp 7.5 -> 21.7 (+14.2), kam +12.1, nus 9.3 -> 20.8 (+11.5), tir 9.4 -> 13.8, amh 14.5 -> 18.9; tiv on SmolSent 18.0 -> 27.1 (`reports/data/final_model_per_language.csv`). Part of this is the finish-rate repair (SFT finished 34-76% of kbp/nus/kea outputs, RL 100%).
- ish, bin, bbj have almost no English-parallel data beyond JW/Bible text (ish 5,221 rows, bin 11,635, bbj 2: `reports/weak_language_data_2026-10-22.md`) and no learned-metric support; their reward is consensus + rules (anchors, GlotLID guard). No benchmark with a human reference exists for ish/bin/bbj in our set (a 230-pair Urhobo silver set made by Gemini is the only calibration material for any of them, and it is not human).
- Controlled ablation AB2 (yor, kin, orm, lin; 49 RL steps, 50k completions, `reports/` and `paper/` Section 8.4): from a weak SFT start RL still gained +7.4 chrF++ [6.8, 7.9] (F start: +5.7), closed 54% of the gap to the strong start, while 3,136 extra in-distribution SFT pairs gave -1.0 chrF++ [-1.5, -0.6] (W_S1P). Much of RL's chrF++ gain at the weak start is repaired unfinished outputs (+18.7 points finished); on sentences finished by all systems the gain is smaller (+1.1 vs +2.3). So 'tiny SFT does little, RL helps' holds in a regime where the languages already had lots of SFT data; it is not evidence about languages with 0-5k pairs.

## Owner's clarification (2026-10-24): the regime to test
Take a language L whose learned quality estimator (QE) encoder supports it, with about 3-5k human pairs: (1) fine-tune the model (which saw some L in pretraining) on about 3k of the pairs (SFT), then (2) improve it beyond that SFT domain with RL against the QE that is good for L. This is arms A3/A4 below with a metric that supports the language. AB2 cannot test it: its four languages already had large SFT data and the weak start was a shortened SFT of the same data, so AB2 only shows that RL still adds a lot on top of a weak SFT and that extra in-distribution SFT does not help there. The five target languages must have QE support for the RL step (ish, bin, bbj have none in AfriCOMET: they need the adapted-metric arm A4).

## Questions
Q1 Metric limit: for a language without a learned metric, does a metric adapted on k human pairs give a better RL signal than consensus + rules?
Q2 Data ladder: with n in {0, 250, 500, 1k, 2k, 4k} human pairs per language, how do SFT(n), RL(0 pairs), SFT(n)+RL and RL with the adapted metric compare in held-out human-reference chrF++ / spBLEU and in reward-independent metrics?
Q3 Cost: GPU-hours and dollars per language per chrF++ point, at a scale that fits an African research lab.

## Design (sketch)
- Languages: ish, bin, bbj, kea, tiv (the owner's five), plus kbp and nus as controls with known RL gains. Gemma 3 pretraining coverage differs by language (owner's condition: some pretraining exposure); record it per language.
- Data: 4k diverse human English->X pairs per language, paid translation with documented contributor consent; split once: 500 held-out evaluation pairs (never used for training, metric adaptation or checkpoint selection), 250 for development, up to 3,250 for the ladder (nested subsets: 250 < 500 < 1k < 2k < 3.25k). Diversity: stratify English sources by domain, length and the triage difficulty band (`reports/triage_difficulty_vs_quality_2026-10-23.md`).
- Adapted metric: fine-tune a small quality estimator on the n pairs with positives = human translations and negatives = our own model's outputs, other-language outputs, shuffled / truncated / copied sources; validate that it ranks human reference above model output and that it does not reward the known hacks (copy, repetition, stuffing) using the project's detector suite; compare to consensus + rules on the same held-out set. A metric trained on references only measures similarity to the n references: say so; human quality ratings (at least 200 per language) are needed to validate it, which needs native-speaker partners.
- Arms per language and n: A0 base (current model), A1 SFT(n), A2 RL with consensus + rules (our current method, n = 0), A3 SFT(n) then RL with consensus + rules, A4 SFT(n) then RL with the adapted metric (+ consensus), one seed first, three seeds for the best two arms.
- Evaluation: held-out human-reference chrF++, spBLEU, finished / loop / wrong-language rates, any available AfriCOMET / SSA-COMET, paired bootstrap; native-speaker spot checks if partners are found; pre-register the decision rule as in AB2.
- Cost basis: measured in AB2 on the RTX PRO 6000 ($1.19/h): one 49-step b64 RL arm took 20 minutes (about $0.4), a 367-step SFT control about 20 minutes, one four-language evaluation about 5-10 minutes. A ladder of 6 values x 4 arms x 7 languages = 168 runs would be about $70-120 including evaluation and 3 seeds for a subset; the real cost is the human data and the validation ratings, not the compute. These are estimates from AB2, not a quote.

## Risks
Reward hacking without a strong metric (anchors v3 and the language-ID guard help but were calibrated on languages with metrics or a silver set); metric trained on few references may favour surface similarity; no native speakers in the team at present (benchmarks only); languages absent from pretraining may not respond; the five languages differ in script / orthography conventions (Esan, Edo, Ghomala orthography is not standardised); results from five languages do not generalise to all.

## Why it fits the paper's research question
It tests the claim of the paper (RL as a data-efficient complement to SFT) in the regime where it matters most, and gives a recipe a small lab can run. The HF correction datasets (long documents and benchmarks, `SabiYarn-MT-benchmark-translations`) can seed the human data and evaluation sets. Wording: 'improvement against human references and human-judgement-correlated metrics', never 'human preferences'.

## 1. Why urh / sid / wal / bas / dua / yao "have no entry", and why they fail

* **They do have an entry** in `anchors_v2.json` (`languages[iso]` with `entity2 / copy / func / pad`, basis `pivot_held`): they are missing only the v1 blocks (`repeat`, `boiler`, `lid_prob`, `lexicon`), because D-56's builder needed human references (FLORES+ dev, SmolSent, ...) and these languages have none; the 13 weak languages without references (bas bbj bin dua ish iso oke sid swc urh wal wes yao) got their v2 blocks from R3's held-out pivot rows (300-600 mostly Bible / JW sentences). Not a missing-data problem.
* **Cause 1 (a length bug in the padding feature, affects ALL languages).** The type / token ratio falls with text length (human documents of < 100 / 100-200 / 200-400 / 400-800 / > 800 words: 0.79 / 0.66 / 0.51 / 0.43 / 0.32), but the v2 thresholds came from sentences and windows of <= ~250 words. Measured on the real human documents (smol_doc + AfriScience papers, 12,649 documents, `longdoc_fp.txt`): v2 `pad` deficit > 0 in 5 / 14 / 31 / **81 / 100 %** of the human documents of those length bins (gate level >= 0.9: 0.1 / 0 / 0.2 / 1.7 / 0 %). The languages whose long-bucket threshold is highest saturate first: v2 `t_ttr[>60 words]` sid 0.74, wal 0.66, yao 0.59, pcm 0.59, kri 0.52 against 0.25-0.46 for languages with real long human text (sag 0.25, fon 0.31, yor 0.40, hau 0.46): a long output with the ordinary type / token ratio 0.30-0.45 gets deficit 0.8-1.0 in sid / wal / yao / kri / pcm and fails the gate. That is the order of the live failure rates (sid 63 %, wal 58 %, yao 32 %, pcm 22 %, kri 16 %). bas 50 % / dua 31 % / urh 26 % (thresholds 0.40-0.44) are not explained by this alone: their policy outputs may also loop or degenerate (the greedy SFT outputs on JW windows show a v2 gate rate of 0-3 %, `policy_flags.md`), I could not reproduce those on the long science prompts without the live outputs.
* **Cause 2 (domain).** Thresholds, the dictionary and the bigram table were all fitted on religious text. The domain study (section 3) shows what that does to out-of-domain human text.
* Not a cause: the false-positive rate on human sentences (v2 blocks of urh flag 0 of 170 silver sentences and 0 of 56 held-out JW rows).

## 2. The v3 recipe (what is different, in answer to the bias-adjustment list)

| point | v2 `pivot_held` | v3 |
|---|---|---|
| thresholds | one pooled quantile (0.5-1 %) of religious text | **per sub-domain** (set, 4- and 10-sentence windows of it) and the LOOSEST over the sets (lowest low-tail, highest high-tail), moved outwards by a margin (lam 4 tail distances; never below half of the quantile, so a threshold cannot reach <= 0 and silence the detector); copy: quantile 99.8 %, floor 0.2 x 1.5 = 0.30 (v2: 99.5 %, floor 0.08) |
| function-word dictionary | geometric mean of the document frequency in training text and in the references of the same domain | words frequent in the training text AND in **every** sub-domain (minimum document frequency) |
| bigram-order feature | religious bigram table | **dropped** for rebuilt languages (padding = type / token ratio only) |
| type / token ratio | plain, window-length thresholds | **segmental** (`ttr_mode seg100`: mean over `n // 100` equal segments, length independent) and real human documents in the rows |
| copy protection | whitelist: >= 4 occurrences, >= 50 % kept, >= 4 letters | loose: >= 2 occurrences, >= 30 % kept, >= 3 letters, learned over all sets; names / numbers / acronyms / URLs protected from the source as before; rows whose "reference" is English text (untranslated web / UI strings; share of English function words >= 0.12) are removed before fitting |
| entities | own drop rates from Bible text (verse numbers, Bible names) | block removed: pooled prior (half weight) |
| use | enabled if its CV FP <= 2 % | `usable` per detector and `gate_ok` (see 4); `usable: false` = the detector is off for that language |

## 3. Measured: how large is the domain shift, and does the recipe remove it? (`v3_domain_study.py`, `study_summary.txt`)

13 languages that have BOTH religious text (R3 pivot held-out rows, R15 JW windows) AND out-of-domain human text: ach (SmolSent, SALT), bas (FineTranslations web), dag (GlotStoryBook, Wikimedia), her (GlotStoryBook, FineTranslations), ibb (IbomMT), kea (FLORES+, FineTranslations), kon (SmolSent, Wikimedia), kri (SmolSent), nbl (SmolSent, GlotStoryBook), ndc (SmolSent), nyn (SmolSent, SALT, FineTranslations), sid (FineTranslations), tsc (GlotStoryBook). The detectors were fitted on half of the religious text ONLY and evaluated on the out-of-domain sentences and 10-sentence windows (101-3,355 per language after removing the rows whose reference is English text) and on the other half of the religious text. Cells: median / p75 / max over the 13 languages of the share of out-of-domain units with a deficit > 0, and the median / max share at the gate level (>= 0.9).

| method | detector | OOD graded FP median / p75 / max | OOD gate-level share median / max | held-out religious text FP median |
|---|---|---|---|---|
| v2 `pivot_held` (what the live run used) | copy | 1.6 % / 2.3 % / 17.3 % | 1.6 % / 17.3 % | 0.0 % |
| | stop-word profile | **34.6 % / 57.2 % / 79.5 %** | 3.0 % / **57.4 %** | 1.6 % |
| | padding | **46.9 % / 64.2 % / 90.4 %** | **14.5 % / 88.0 %** | 0.6 % |
| v3 recipe (lam 4) | stop-word profile | 14.7 % / 15.7 % / 41.5 % | 0.3 % / 4.6 % | 1.1 % |
| | padding (type / token ratio only) | **0.0 % / 1.2 % / 76.4 %** (sid web text) | 0.0 % / 1.1 % | 0.0 % |
| v3 copy 0.2 x 1.5 | copy | **0.2 % / 0.4 % / 6.0 %** (dag, sid) | 0.2 % / 6.0 % | 0.0 % |

Reading. (a) The religious-text calibration is NOT safe for other domains: the gate-level share of the v2 method on out-of-domain human text is 3 % (stop-word) / 14.5 % (padding) at the median and up to 57 % / 88 %; this reproduces the live behaviour. (b) The v3 recipe brings padding and copy to <= 1 % (median 0 %), and the stop-word profile's gate-level share to <= 4.6 %, but the GRADED stop-word FP stays at ~15 % (p75 16 %, max 42 %): a function-word profile fitted on religious text is a poor model of other domains. Therefore **the stop-word profile is `usable: false` for every language that has no out-of-domain held-out set** (13 of 16 rebuilt languages) and never reaches the gate. (c) Padding and copy have a few bad languages: sid (web text with English strings and UI vocabulary: padding 76 %, copy 3-8 %), bas (padding 28 %), dag (copy 6 %): they are `usable: false` where that language's own out-of-domain set fails the leave-one-set-out rule.

## 4. The v3 entries (16 languages; `calibration/anchors_v3.json`, per-language `basis`, `usable`, `gate_ok`, `usable_reason`, `lodo_per_set`)

Rules. Wherever a detector is `usable: false` the reward ignores it for that language (`Anchors2._blk2` returns None); `gate_ok: false` keeps it out of `anchors_stuff_gate` (new `Anchors2.gate_ok`, reward hunk in `_stuff_gate`, 2 conditions).

Same method otherwise; CV FP 1.1 % (pad), 1.5 % (stop-word). ## 5. The Gemini Urhobo silver set (230 pairs; GENERATED BY GEMINI, not native-verified; treated as silver: a check, never a threshold)

Rules applied: nothing is fitted on it (no threshold, no function-word profile, no loanword list, no weight mix, so the 0.75 / 0.25 rule was not needed); the `basis` string of urh in `anchors_v3.json` reads `pivot_held(597)+r15_seen(59)+r15_val(112); domain-robust v3 recipe (...); jw_pivot + gemini_silver_check (the 230 Gemini-generated pairs are NOT native-verified: used only to check ...)`: the JW / pivot text is the **jw_pivot** source and the silver set is only the `gemini_silver_check` (`scripts/urh_silver_check.py`, never `build_anchors_v3_calibration.py --bench`, which is for native-verified text).

## 6. Re-running the calibration with the owner's native-verified Urhobo benchmark

```
cd /workspace/jobs/r9/gemma_mt_r9      # or the run tree
export PYTHONPATH=$PWD:/workspace/sft_build/pylibs
python scripts/refit_urh_bench.py --iso urh --bench /path/urhobo_native.jsonl \
    --cal /workspace/jobs/r9/assets/calibration/anchors_v3.json --funcwords /workspace/jobs/r9/assets/calibration/funcwords_v1.json \
    --out /workspace/jobs/r9/assets/calibration/anchors_v3_urh_refit.json --dev-out /workspace/jobs/r9/urh_dev.jsonl --dev-name urh_dev
```
Input: jsonl rows `{"english": ..., "reference": ...}` (`urhobo` accepted instead of `reference`). It (a) prints the false-positive share of every detector of the current entry on the benchmark with the 95 % upper bound, (b) refits urh with the benchmark as one more out-of-domain set (same recipe; the benchmark can only loosen a tail threshold, the copy threshold is kept at max(old, new); `usable` / `gate_ok` from the leave-one-set-out numbers with the benchmark held out; rows already present in the other sets are dropped), writes the new calibration file, (c) writes the dev harness file and prints the `benchmark_aux` yaml entry (`bench_aux/urh_dev/chrf/urh`). Tested on a stand-in (120 SmolSent rows of kri). **What ~100 sentences can resolve**: 0 flags of 100 prove only "FP <= 3.0 %" (1 of 100: <= 4.7 %, 2 of 100: <= 7.0 %); a 1-2 % rate is indistinguishable from 0; so a 100-sentence benchmark can switch a detector OFF (a visible FP) but cannot certify gate level or a rate under 3 %: `gate_ok` stays false for urh unless the benchmark is >= ~300 sentences with 0 gate-level flags.

## 8. Risks and weak evidence

1. The domain study uses 13 languages and human out-of-domain text; policy outputs are worse than human text, so a human FP of 0-1 % does not bound the failure rate of the policy; the gate is therefore off for every rebuilt language.
2. The live failure of bas / dua / urh (26-50 %) is not explained by the length bug alone (thresholds 0.40-0.44); I could not obtain their live outputs. If it persists with v3, the policy outputs themselves are degenerate and `fail/stuffed_output` is doing its job.
3. FineTranslations (sid, bas, ...) has machine-made English sides and target text with English strings; rows with an English share >= 0.12 were removed, mixed rows remain, so sid / bas out-of-domain FPs are pessimistic.
4. The stop-word profile's graded FP remains ~15 % out of domain even with the recipe: it should stay a small weight (0.3) and off where no out-of-domain set exists.
5. Silver set: 230 LLM-generated sentences; agreement scores are not translation quality; its low flag rates only show that nothing is wrong with it as seen by these detectors.

# E-09b: the SFT in fp32 on the full headline set (2026-11-04)

Question (coordinator, from E-09): on the 240-sentence parity set the SFT gained +1.81 chrF++ [+0.59, +3.12] from fp32 over bf16, the earlier 4,000-sentence study only +0.24 [-0.07, +0.55]. Does the bf16 headline understate the SFT and so overstate the RL gain? Run: the SFT final (`g15_385m_sft_final`) through the headline harness with vLLM in **float32** (`--dtype float32`, which now reaches the vLLM engine; harness change logged in `overnight_log_2026-11-04.md`, 09:15 row), greedy, 768 new tokens, the same 122,585 rows (FLORES+ devtest 54 languages, NTREX 24, MAFAND 15), 214 contamination-flagged rows removed, the same paired bootstrap as the evidence report. Data: `reports/data/e09b_fp32_2026-11-04/evidence_e09b.json`.

**Status: partial, by order.** The fp32 SFT generation finished (14 of 14 units, 18:38 UTC; started 17:46 next to the long-RL evaluation at a 0.15 GPU share). The AfriCOMET scoring was not finished when the run was stopped at 18:46 to protect the E-03 trainer (coordinator order); predictions were assembled from the cached generations on the CPU only (`CUDA_VISIBLE_DEVICES` empty). The fp32 RL run was not started (it needs a vLLM engine); the RL model was measured only in the 240-sentence parity set (fp32 vs bf16 +0.09 [-0.41, +0.59]). Partial AfriCOMET (40 % of the rows were scored) is not reported here.

## Result

| chrF++ (language macro) | SFT bf16 | SFT fp32 | fp32 minus bf16 [95 % CI] |
|---|---:|---:|---|
| FLORES+ devtest (54) | 22.85 | 22.69 | -0.16 [-0.29, -0.02] |
| NTREX (24) | 29.25 | 29.33 | +0.08 [-0.08, +0.25] |
| MAFAND (15) | 35.77 | 35.99 | +0.22 [-0.03, +0.50] |
| **all 93 cells** | 26.59 | 26.55 | **-0.04 [-0.13, +0.07]** |

* **fp32 does not help the SFT on the full set**: -0.04 [-0.13, +0.07] chrF++ over the 93 cells, plain chrF -0.08 [-0.19, +0.03]. Finished / loop rate on FLORES+: bf16 0.829 / 0.2095, fp32 0.805 / 0.2108; length ratio 3.03 / 3.18. The SFT's runaway outputs are not a bf16 rounding artefact. On rows where both versions finish without a loop fp32 is slightly better (+0.30 chrF++ [+0.27, +0.34]), because the two versions fail on slightly different sentences.
* The +1.81 of the 240-sentence set was a small-sample result (10 languages x 24 sentences, a few runaway outputs moving the macro); the 4,000-sentence study (+0.24) and this full set (-0.04) agree on "about zero".
* **Bound on the headline:** the RL gain over the SFT is +8.81 [+8.59, +9.03] on FLORES+ against the bf16 SFT and **+8.97 [+8.71, +9.20] against the fp32 SFT** (mixed best, bf16); over all benchmarks +7.96 against bf16 SFT. The bf16 harness therefore does **not** overstate the RL gain: if anything the fp32 SFT is 0.16 chrF++ lower on FLORES+; the upper end of the all-cell interval (+0.07) bounds any possible understatement of the SFT at 0.07 chrF++.
* Caveat: the RL model's own fp32 run was not done; its sensitivity is measured only on the 240-sentence set (negligible). Together with E-09 this settles the engine/precision question for the paper: report vLLM bf16 as the headline and state the fp32 SFT control (-0.04 [-0.13, +0.07] over 93 cells) and the engine agreement in fp32 (98.8 % / 97.1 % identical outputs).

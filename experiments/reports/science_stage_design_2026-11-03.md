# Science stage of the 385M model: SFT, then RL (arm 2). Design, 2026-11-03

Owner decision: science stage as **SFT then RL** first (arm 2); the RL-only arm is a later comparison. Arabic / Berber / Dinka stay out (arz, zgh/tzm, shi, dik). This is a design, nothing is started, and nothing is armed: several points below are uncertain (section 7) and the reward code of section 3 does not exist yet. VERIFIED = read from the repo or the box today; PLAN = proposed; ESTIMATED = not measured.

## 0. Place in the queue
mixed stage (running, cap 60 steps) -> weak West-African group run (armed, waiter `weak_waiter.sh`, 150 steps cap) -> **science SFT (about 0.5 h)** -> science SFT evaluation (AfriScience dev/test, NTREX/MAFAND clean, held-out AfriCOMET; about 20 min) -> **science RL** -> evaluation. To keep the GPU busy, the science-SFT waiter (same pattern as `weak_waiter.sh`: waits for `runs_385m_weak/mixed/summary.json` and no trainer process, token only in the process environment) is armed once section 7 is answered. If the science-RL code is not ready when the SFT evaluation ends, the GPU runs the weak-group second round or the matched baseline control (`experiments_after_stage_A_2026-11-03.md` arm a) instead of idling.

**Mixture.** About 35% science tokens / 65% replay (old stage 34.5% / 65.5%): science about 13 M tokens (6.6 M target tokens x 2 passes), replay about 24 M, total about 37 M tokens = about 280 steps at 131k tokens per step. Held-out: AfriScience **dev** (843 sentences x 6 languages + 25 papers) is used only for validation and early stopping, never trained on; AfriScience **test** is never seen by any stage (index check on both sides of every window; the final check decodes the packed tokens and must print `HITS_samples 0`). A replay validation slice gives the forgetting curve.

**Trainer.** The 385M SFT trainer and its recipe (Muon, micro-batch 8 x accumulation 4, 131k tokens per step, packed varlen attention, fused loss, checkpoint every 20 steps) with a small peak LR **5e-6** (the last SFT shard decayed from 3e-5 to 3e-6; the old 270M science stage used AdamW 3e-6) and 10 warm-up steps, linear decay to 10%; weight decay 0. Early stopping on the AfriScience dev loss with patience 3 evaluations. Checkpoints to `/dev/shm` (disk has 5.9 GB free). Output: Hub `<HF_ORG>/gemma-0.4B-science-sft`, no model card. **Risk to test on CPU first:** the SFT pack format stores a fingerprint of the original Gemma tokenizer (tags are the `<unusedK>` ids), while the RL checkpoints carry the renamed tokenizer (`<yor>`); ids are identical, so the SFT trainer must be fed the original tokenizer directory with the RL weights (check the fingerprint guard and the tag-id table on a 4-step CPU smoke).

**Drift control.** Small LR, short run, 65% replay, plus the interpolation sweep of the old stage: theta(alpha) = alpha x theta_RL-start + (1 - alpha) x theta_science-SFT for alpha in {0, 0.3, 0.5, 0.7} (about 1 min each to write, 2 min each to evaluate on the dev sets), choosing the alpha with the best AfriScience dev chrF++ subject to NTREX/MAFAND dev not lower by more than 0.5 and every weak group not lower by more than 0.5 (the old rule, choice rule at line 153 of `sft_science_stage_2026-10-21.md`).

## 2. Evaluation after the SFT and after the RL
Same harness, greedy, 768 new tokens (`eval_385m` scripts, which have the single-token tag mode): AfriScience-MT **test** sentence level (and document level for the 28 test papers if time allows) with plain chrF (word order 0) and chrF++; NTREX and MAFAND **clean rows** for non-regression (the languages both cover); held-out AfriCOMET (`masakhane/africomet-stl-1.1`, never a reward model, 41 languages); per language, bootstrap intervals for the 385M systems; columns for the old 270M (RL-final 47.9, science-stage A2W 50.0, final2 step 401 50.2 macro on AfriScience test, stored; NTREX / MAFAND clean from `own_270m_per_language.csv`) and the published fine-tuned systems (NLLB-1.3B 52.3, NLLB-600M 51.7, M2M100-1.2B 48.2). **From this stage on the AfriScience comparison with the old 270M is fair** (both have had a science stage); the earlier post-B1 report marks it not comparable. Pre-registered reading (PLAN): the science SFT is kept if AfriScience test macro chrF improves by at least 3 over its start and NTREX / MAFAND clean macro does not drop by more than 0.5; the science RL is kept if it adds at least 1 chrF++ on AfriScience test over the best SFT alpha with held-out AfriCOMET not lower by more than 0.005.

## 3. Science RL after the SFT (needs new code)
**Prompts.** Science pool `clean_sci_v2` (PMC, arXiv, LibreTexts, AfriScience train English; 109,651 prompts after the clean filter, b64 / b256 bins used; LibreTexts licence conflict unresolved, 10,257 prompts, `--exclude-source libretexts` removes it) + general and news prompts as before. Domain mix as in the old final run: 70% science / 30% general. **Reference prompts** (domain `ref`): AfriScience train windows with human references in the 6 languages (amh hau lug nso yor zul), as many as the protected index leaves (the ref pool of the earlier patch has about 1,670 rows per language; rebuild with all train windows, 5,792 sentences + windows per language), weighted high inside the science share ("reference-heavy": 50% of the science draws for these 6 languages). **Reference-free science prompts** (QE reward as now) for the other 75 languages, which have no science references.

**Reward on reference rows** r = (1 - w) r_existing + w r_ref, w = 0.6, where r_ref is a small-weight sum:
1. **Reference-based SSA-COMET-MTL** (`McGill-NLP/ssa-comet-mtl` with source + hypothesis + reference; `CometScorer` already supports UnifiedMetric with a reference, mean of the three views, `rl/comet.py` lines 100-137). NOT `africomet-stl-1.1`, which stays the held-out monitor (so gaming of the SSA reward shows up on a different model). Needs a new reward-worker path (`reference_based` is implemented for the AfriCOMET worker; the SSA-MTL worker is started reference-free in the ensemble).
2. **chrF++ shaped** against the reference (existing `reference_weight` term, `consensus_value` map).
3. **Separate chrF recall and precision terms**: omission term = penalty when chrF recall is below the reference-row quantile of the previous stage (too short or dropped content), addition term = penalty when chrF precision is below its quantile (hallucinated or padded content); each weight <= 0.1 of the reward range; the existing length-ratio failure class and `pad` anchor remain.
4. **Number / unit / acronym / named-entity preservation**: extends `anchors.py` (`entity_num`, `entity_name` penalties exist, penalty only, never a bonus) with a unit and acronym channel (regex for SI units, percentages, chemical formulas, all-caps tokens of >= 2 letters); penalty only, weight <= 0.1; judged only on rows where the source has at least one such item.
**Gaming watch** (logged per step and per language): rates and means of each new term, copy-source rate, length ratio against the reference, share of outputs that equal the source's numbers / entities verbatim (a precision exploit), SSA-reference vs held-out AfriCOMET divergence at every dev evaluation (the existing hacking alarm already needs QE up while chrF++ and AfriCOMET fall).
**Keep:** patch-3 monitor, hacking alarm 0.75 / 0.03, KL guard 0.25, combined dev early stop with 50 steps of patience (`early_stop_dev_k` 2, AfriCOMET required), beam guide 0.25, MBR guide for the weak list, dynamic sampling oversample 1.0. Cap 150 steps. Output `<HF_ORG>/gemma-0.4B-science-rl`.
**Code to write (not started):** reference-based SSA-MTL scoring in the reward worker; recall / precision / unit-acronym terms in `reward.py` / `anchors.py` with CPU tests; the science domain mix keys in the stage yaml (`rl_F_final.yaml` already has the 70 / 30 science / general draw and the 150-step cap); the rebuilt reference pool. ESTIMATED 1-1.5 days of implementation and tests, which is longer than the SFT (0.5 h) plus its evaluation (0.3 h); hence the fallback in section 0.

## 4. Languages
Science SFT: the 6 AfriScience languages (science part) + replay over all 81 RL languages minus none excluded here (Arabic / Berber / Dinka are not in the 81). Science RL: reference rows for the 6, reference-free science prompts for the 75 others. Evaluation: AfriScience test covers only the 6; the other languages are monitored on NTREX / MAFAND clean and held-out AfriCOMET (no science references exist for them: whether science gains transfer to them is a hypothesis, measured only by QE and by non-regression).

## 5. Licences used (disclose)
AfriScience-MT train: Apache-2.0. Replay: the general SFT data (NLLB-mined bitext, Aya aligned part, Tumbuka instruction sets, others as listed in the SFT data report). RL prompts: FineWeb-Edu (ODC-By), Wikipedia (CC BY-SA), PMC / arXiv (CC BY / CC0), LibreTexts (unresolved, CC BY vs CC BY-NC-SA), BBC / Wikinews / Global Voices news (BBC: no declared licence, reward-only prompts). The reward uses NLLB pseudo-references with a low weight (disclosed earlier). No NLLB / TranslatePsy text is used as SFT target in this stage.

## 6. Cost (ESTIMATED)
SFT 0.5 h (+ alpha sweep and evaluation 0.5 h); RL 150 steps at 40-110 s per step = 2-4.5 h with the guides; evaluations 0.3 h each. Disk: checkpoints in `/dev/shm`.

## 7. Uncertain points: decisions or checks needed before anything is armed
1. **Other science / health parallel data.** Only AfriScience train is confirmed. A catalogue scan could add data for more languages; without it the science SFT teaches six languages and the replay protects the rest. Run the scan (CPU) now? (recommended)
2. **SFT optimizer and LR.** Owner: "existing SFT trainer / hyperparameters with a small LR". The existing trainer is Muon; the only measured small-LR science recipe is AdamW 3e-6 on the 270M. Proposed: Muon 5e-6 with the interpolation sweep as the safety net; alternative AdamW 3e-6.
3. **Tokenizer fingerprint** of the SFT packs versus the renamed-tag tokenizer of the RL checkpoints (section 1): needs the CPU smoke before the first GPU minute.
4. **LibreTexts in the science RL prompts** (licence unresolved, 10,257 prompts): include (disclosed) or exclude?
5. **Hub visibility and storage:** the `gemma-0.4B-science-sft` / `-rl` repos have the same private-storage-cap problem; the visibility of the translate-rl repo is currently reset to private by the trainer's pusher.
6. **Science RL code** does not exist yet (section 3); the start of the RL stage is gated on it and on the SFT evaluation.
7. **Start checkpoint** after the weak run: the rule in section 1 uses both dev chrF++ and held-out AfriCOMET; confirm.
8. The old stage mixed in a RL best-translation archive, long-document distillation and anchors (A2W, 5% / 14% / 7%); this design drops them (human references and replay only), as the owner specified. The old A2W recipe is the reference for the alpha sweep.

# RL stage plan of the 385M model, context capped at b256 (2026-11-02)

Owner decisions 2026-11-02: (1) cap the RL context at b256 (no b512 / b1024 stages): production translation is sentence by sentence, and in the decoding study sentence-by-sentence beats whole-document decoding by 20-29 chrF++ at b1024 and longer (`reports/generation_config_study_2026-10-22.md`); (2) keep every finish / end-of-turn / loop / length / language rule on the short bins; (3) apply the long-document reward (`longdoc_v2`) to the short bins too. Laptop only; nothing was run on a GPU. Numbers marked ESTIMATED come from the 270M plan's step times (the 385M step times are measured by the preflight).

## 3. Long-document reward on the short bins (`longdoc_v2` with `longdoc_min_src_words` 1 in every stage including the preflight)

Every source of >= 1 word goes through the longdoc path. What differs from the normal path for a short source (checked in code and by `tests/test_longdoc_short_bins.py`):

* **Identical:** a normal translation of one to seven chunks. `aggregate_tail` returns the plain weighted mean below 8 chunks (`min_chunks`), the same function the normal path uses; severity is 0; the reward is equal to 1e-9 (test). `cvar_excess` and its `tail_gap` calibration never act on short sources.
* **Different:** (1) the v1 whole-text repetition guards (`is_repetitive`, and `is_self_repetitive` in blend / consensus languages) are replaced by the continuous severity (reward pulled towards -2 by s x (r + 2); s = 1 -> status `degenerate`); (2) a stuttering sentence makes its CHUNK a failed chunk (-2 for that chunk, other chunks keep their reward); (3) coverage severity: `0.5 x` the failed share of the source pulls a partly failed output further down (2 chunks, 1 failed: mean -0.25 -> -0.69); one failed chunk of one is -2 either way; (4) anchored alignment (numbers / names) instead of Gale-Church when the sentence counts differ; (5) samples with severity >= 0.5 stay out of the consensus pool.
* **No degeneracy:** empty text, one word, 0-3 chunks, a fully failed source: all finite, never below -2, never above the plain mean (test `test_zero_to_three_chunks_do_not_degenerate`).
* **Catches on short outputs:** loop 15x one word (severity 1.0, level cycle), 3-word cycle x8 (1.0), a sentence duplicated 2x (1.0) or 4x (1.0), 40 words + loop tail (0.95). The v1 guard misses the 2x duplicate in QE-mode languages.

Calibration (`longdoc_v2.json`; the clean refit `longdoc_clean.json` lives on the RL box and was not available here): buckets are edged at 60 / 230 / 560 / 1000 / 2000 source words, so b64 = bucket 0 and b256 = bucket 1. Buckets 0 and 1 have **identical limits** (rep4 0.10, cover8 0.062, dup_sent 0.03, dup_block 0.03, cycle 0.02) and `tail_gap` has data for buckets 1-5 only: bucket 0 (b64) borrows bucket 1's limits. The n-gram levels do not judge texts below 24 words, so on b64 outputs only `cycle` and `dup_sent` can fire. False positives on **human short text** (FLORES+ dev, 45 languages, no source-excess correction = the strict case): severity > 0 in 0.09 % of 44,865 sentences (>= 0.5 in 0.01 %, 1.0 in 0 %) and 0.07 % of 13,500 three-sentence blocks (>= 0.5 in 0 %), against 0.00 / 0.01 % for the v1 guards. So the thresholds are usable for short sources. **To check when `longdoc_clean.json` is at hand:** rows 0 and 1 of `t0` / `tail_gap` and `meta.n_docs` per bucket.

Diagnostic (`reward.longdoc_compare_v1`, on in the generated yamls, rewards unchanged): `longdoc/delta_reward_{short,mid,long}` (longdoc-path reward minus the plain-mean chunk reward of the same sample; short = <= 60 source words), `longdoc/delta_nonzero_rate_*`, `longdoc/n_*`, `longdoc/v1_reject_rate`, `longdoc/v1_only_reject_rate` (v1 would reject, longdoc keeps) and `longdoc/ld_only_reject_rate` (longdoc rejects, v1 would not). Expectation to verify in the preflight: delta ~ 0 for normal samples, `ld_only_reject_rate` and `v1_only_reject_rate` small.

## 6. OPTIONAL stage F2 "final_long" (owner 2026-11-02): science, b1024 + b2048, OFF by default

**What it is.** A short RL stage after the final run F that trains the model to finish and not loop on whole papers. It is NOT part of the five-stage plan: the default plan, its totals (665,920 completions, section 2 cost) and the launcher chain are unchanged. Evidence to keep in mind: the 270M RL taught nothing at these lengths in phase 2c (b1024 reward flat, b2048 eval reward -1.71 to -2.00 at all 22 evaluations, `reports/lean_schedule_clean_rerun_2026-10-28.md`), so F2 is a bet that needs its gate; and production translates sentence by sentence, so F2 only pays if whole-paper output matters.

### 6.3 Memory and micro-batch (from `reports/rl_gpu_ram_385m_2026-11-01.md`; ESTIMATED, no 385M run has happened)
Sequences reach ~9.5k tokens. Without checkpointing the trainer needs ~47 GB at 24,576 tokens per micro-batch (the ladder start) and one sequence of 9.5k already takes 40 % of that, next to vLLM and the scorers (75 GB on 96 GB, 72 GB on 80 GB: no headroom for long sequences). F2 therefore sets **`gradient_checkpointing: true`** (trainer ~15 GB, compute +25-35 % of the update part only) and **`vllm_gpu_memory_utilization` 0.30** (a bigger KV pool for the long sequences: 24 GB on 80 GB, 29 GB on 96 GB). Estimated total on 80 GB: ~15 + 24 + 9 = 48 GB, so it also fits a 48 GB card (15 + 14 + 9 = 38) with a small KV pool. The launcher ladder still starts at 24,576 tokens per micro-batch (`LADDER_START=1`); micro-batch = tokens // longest sequence = 2 sequences, accumulation keeps the step size. First 3 steps: watch `nvidia-smi` per process and the vLLM concurrency; if rollouts crawl, raise the utilisation (96 GB) before touching the batch.

### 6.4 Launcher
`STAGE_PLAN=b256+long` (or `EXTRA_STAGES=F2` with `STAGE_PLAN=b256`) allows `launch_clean_rerun_385m.sh run F2`. Without it, `run F2` exits 2 ("OPTIONAL and OFF"). ### 6.5 Pre-check: do we run F2 at all? (`clean_rerun_tools.py f2-precheck`)
After the science SFT and the final run, one greedy pass over the AfriScience-MT dev papers with the final model, whole paper in ONE prompt:
```
python scripts/eval_afriscience.py --model <F> --splits dev --levels document --max-new-tokens-document 7168 --vllm-python ... --out dev_F
python scripts/clean_rerun_tools.py f2-precheck --preds dev_F/predictions_dev.json --out f2_precheck.json
```
**SKIP** (exit 10) when the finished rate is >= 97 % **and** the loop rate (`rl.guards.is_repetitive`, the trainer's definition) is <= 2 % (the preflight's greedy loop limit; "low" was not defined by the owner, this is my choice); otherwise **RUN** (exit 0). Fewer than 150 papers (25 x 6 languages) is INVALID (exit 1). The pass costs 0.08 / 0.15 / 0.30 h (USD 0.10 / 0.18 / 0.36) and is spent either way.

### 6.6 Gate: keep F2 or discard it (`clean_rerun_tools.py f2-decide`)
Same dev papers (25 per language, one greedy pass each, F and F2, same decoding), per-paper chrF (sacrebleu `CHRF(word_order=0)`, NFC). **KEEP_F2** if (A) the lower end of the paired-bootstrap 95 % interval (10,000 resamples of the 150 papers, percentile) of the mean paper-chrF difference F2 - F is above 0, **or** (B) the finished rate rises by >= 2 points and the mean paper chrF of F2 is not lower than F's. Otherwise **DISCARD_F2** and F stays the model (exit 0 / 10; 1 = invalid). Additionally the sentence-level dev chrF++ of both models can be passed (`--sentence-base/--sentence-new`): a fall > 0.5 is REPORTED as a warning, it does not change the verdict (my addition: the owner's rule looks at papers only, production is sentence by sentence). The training health gate (`gate --stage F2`: KL, grad norm, loop rate, dev finished rate, dev chrF++ drop >= 1.0) runs as for any stage. With 150 papers, 2 points are 3 papers: criterion B is a coarse rule; A is the stricter one.

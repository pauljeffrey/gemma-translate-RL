# E-02: beam-4 and MBR-16 at 768 new tokens on the SFT and on the RL model (2026-11-05)

Executor: the E-02/E-04/E-11/E-14 agent (second GPU queue of 2026-11-05). Scripts: `data_pipeline/sft_clean/fresh/overnight/e2405/` (copied to `/workspace/e2405/` on the A100). Results are added below section 0 after the run; section 0 is not edited after the first generation has been looked at.

## 0. Pre-registration (written 2026-11-05 05:10 UTC, before any E-02 generation exists)

**Question.** The existing decoding study (SFT only, 256-token cap, `reports/data/...decode_m385`, ledger D1/D2/D5) says beam-4 and MBR-16 beat greedy on the SFT. With the cap raised to 768 (the cap of every other number in the paper), is the beam/MBR gain still there, and is the RL gain additive to it or is it (partly) the same repair?

**Systems (6).** Two models x three decoders, same 4,000 prompts for all six.
* SFT = `<HF_ORG>/gemma-0.4B-translate-sft` (box copy `/workspace/clean_rerun/models/g15_385m_sft_final`, model.safetensors sha256 f1f770a88abb...).
* RL = mixed best = Hub `<HF_ORG>/gemma-0.4B-translate-rl`, branch `main` (box copy `/dev/shm/rl_mixed_ckpt/best`, sha256 8cb0dd5af976..., verified equal to the Hub LFS hash on 2026-11-05).
* greedy (temperature 0); beam-4 (vLLM `LLM.beam_search`, width 4, length penalty 1.0, 768 new tokens); MBR-16 (greedy + 16 samples at T 0.7, top-p 0.95, seed 0; candidate = sentence chrF++ of sacrebleu with word order 2; the output is the candidate with the highest mean chrF++ against the other 16). **MBR is labelled "metric-matched": its utility is chrF++, which is also the headline metric, so chrF++ gains of MBR are partly by construction; spBLEU, chrF and held-out AfriCOMET are reported beside it and are what to read.**
* **Sentences:** 20 languages (yor hau ibo swh amh zul xho kin som wol lug sna twi ewe lin tir orm nso tsn afr) x 200 FLORES+ devtest sentences (every 5th, index 0, 5, ..., 995; the sentences of the existing decode study). 4,000 rows per system. The 214 contamination-flagged rows of the harness are removed if any of them falls in this set (the number removed is reported).
* **Engine/settings (identical for all six):** vLLM 0.32.0, bfloat16, `enforce_eager`, `max_model_len` 2048, 768 new tokens, stop tokens {`<eos>` 1, `<end_of_turn>` 106}, prompt = `gemma_mt.format.build_prompt` (single-token tag mode), no frequency/repetition penalty, no n-gram block (no decode-time guard of E-01), GPU util 0.6, nothing else on the GPU.
* **Beam end token (a fix, stated up front).** vLLM 0.32.0 `beam_search` completes a beam only on `tokenizer.eos_token_id`, which is `<eos>` (1) for this tokenizer, not `<end_of_turn>` (106). The 256-token study therefore ran every beam past its end-of-turn to the cap and cut the output at the first end token afterwards, ranking beams by a score that includes tokens after the end of the answer. For E-02 the engine gets a copy of the tokenizer whose eos is `<end_of_turn>` (asserted `eos_token_id == 106` at start); the old behaviour is re-run as a labelled diagnostic (`beam4_oldeos`, both models) to show what the old study measured. Primary beam = the fixed one.

**Metrics (all per language, then macro over the 20 languages; AfriCOMET macro over the languages for which the harness has held-out AfriCOMET-STL-1.1 scores, the same set as in the E-01 evaluation).** Primary: chrF++ (sacrebleu CHRF word_order 2, NFC, corpus statistics per language). Beside it: chrF (word order 0), spBLEU (sacrebleu BLEU, `flores200` tokenizer), held-out AfriCOMET-STL-1.1 (`masakhane/africomet-stl-1.1`, reference-based, never a reward), finished rate (an end token before the 768 cap), loop rate with BOTH detectors (reward-family flag `guards.is_repetitive or is_self_repetitive`; independent detector of E-08: lzma residual, repeated char 8-gram share, repeated word 3-gram share, thresholds from `reports/data/degeneration_audit_independent_2026-11-04/thresholds.json`), output/reference length ratio. SSA-COMET-QE is not used (reward family; not needed for a decoding question).

**Statistics.** Paired bootstrap, Poisson(1) weights per source sentence shared by all systems and all languages (the 200 English sentences are the same in every language), 1,000 resamples, seed 20261104; percentile 95% intervals on every macro and every difference (`ecompare.py`). Within one model there is no training-seed noise; the intervals are sentence-sampling intervals. Across models the comparison is one SFT run against one RL run (seed noise of RL is E-04's subject).

**Comparisons and decision rules (fixed now).**
1. Decoder effect on each model: beam-4 minus greedy, MBR-16 minus greedy (chrF++, spBLEU, AfriCOMET, finished). A decoder "helps" if the interval of chrF++ and of AfriCOMET both exclude 0 on the positive side; "helps on chrF++ only" otherwise (flagged as possibly metric artefact; for MBR always flagged).
2. Does decoding replace RL? D = RL greedy minus (the better of SFT beam-4, SFT MBR-16 by chrF++), paired. Lower 95% bound of D > +1.0 chrF++ and AfriCOMET lower bound > 0: RL is not matched by decoding. Interval inside (-1.0, +1.0): decoding on the SFT matches RL. Upper bound < -1.0: decoding on the SFT beats RL.
3. Is the RL gain additive? Gain under decoder d: G_d = RL_d minus SFT_d. Report G_greedy, G_beam, G_MBR and the interaction I_d = G_d - G_greedy with intervals. "Additive" if the lower bound of G_beam (and of G_MBR) stays > +1.0 chrF++ and the interval of I_d contains 0; "partly redundant" if G_d is smaller than G_greedy with an interval of I_d excluding 0.
4. The ESTIMATED beam gain over a 768-cap greedy of +5.0 (EXPERIMENTS_LEFT E-02) is checked against the measured one.
5. Noise: ties and sign changes inside the intervals are reported as such; differences below 0.5 chrF++ are not interpreted (E-04 will give the seed spread of the RL; none exists for decoding).

**Not done / out of scope:** language-specific decoding policy, other beam widths, length penalties, beam on all 54 FLORES+ languages (E-19), human evaluation. If the beam run (768 steps for 4,000 prompts in vLLM, no early stop) is too slow the fallback is the same vLLM beam loop with the Hugging Face early-stopping rule (an instance stops when 4 completed beams exist and no active beam can beat the worst of them); it would be reported as "beam-4 (early-stop rule)" and is only used if the full run cannot finish.

### Amendment 1 (2026-11-05 06:05 UTC; after a 120-sentence smoke test of the SFT, before any real E-02 generation or score)
The smoke test (SFT, first 120 of the 4,000 items, no metric computed) showed that vLLM 0.32.0 `LLM.beam_search` as registered above is not a usable beam-4 at 768 tokens: with the end token fixed (eos 106) it still runs every instance to the cap and ranks ended and still-running beams by cumulative log-probability divided by length, so a runaway continuation beats every ended hypothesis: **0 of 120 outputs ended** (all 768 tokens; the text continues past the answer with commentary), 707 s for 120 sentences. A beam search that stops when 4 hypotheses have ended is the standard definition (fairseq / Hugging Face `early_stopping=True`). Therefore: **primary `beam4` = vLLM's beam step (width 4, length penalty 1.0, eos 106, 768 cap) with the stopping rule "an instance stops when 4 hypotheses have ended; only ended hypotheses are candidates"** (smoke: finished 1.0, 45 s for 120). `beam4hf` = the Hugging Face `early_stopping=False` rule (stop when the best running beam cannot beat the 4th ended hypothesis; running beams also compete at the end), run as a secondary system. The unmodified vLLM loop is reported only as the 120-sentence smoke observation above; the old study's configuration (eos = `<eos>`) is not re-run (optional diagnostic `DIAG=1`, lowest priority). Everything else of section 0 (metrics, decision rules, sentences, engine) is unchanged; the decision rules use `beam4` and treat `beam4hf` as a robustness check. A consequence for D1/D2 (256-token study): its beam numbers came from the unmodified loop with eos = `<eos>`; they are not comparable to E-02's beam-4 and the report says so.

## 3. Verdict against the pre-registered rules

1. **Decoder effects.** SFT: beam-4 and MBR-16 both help on chrF++ AND held-out AfriCOMET (beam +3.71 / +0.013, MBR +5.96 / +0.027); MBR also helps on spBLEU, so its chrF++ gain is not only metric-matching, but it is the largest on exactly the metric it optimises, and it is the stronger of the two on chrF++ and AfriCOMET while beam-4 is higher on spBLEU. RL: **MBR helps** (+0.92 chrF++, +0.009 AfriCOMET, intervals above 0); **beam-4 (stop at 4 ended) does not help and costs 0.77 chrF++** (AfriCOMET difference inside noise): it shortens the output (length ratio 0.98 against 1.05 for greedy), and chrF++ rewards recall; spBLEU does not drop. The HF-rule beam (running beams also compete, outputs longer) gives +0.83 chrF++ and +0.015 AfriCOMET on the RL model. So the sign of the RL beam result depends on the stopping rule; for the SFT the width rule is far better than the HF rule (+3.7 against +1.0), because the HF rule keeps the SFT's looping outputs (finished 0.897).
2. **Does decoding replace RL? No.** RL greedy minus the better SFT decoder (MBR-16): **+1.60 chrF++ [+1.34, +1.88]** (lower bound > +1.0) and **+0.0302 AfriCOMET [+0.0270, +0.0335]** (> 0): RL is not matched by decoding the SFT, not even by the metric-matched MBR-16 with 17 candidates (which costs about 17x the compute per sentence). Against the SFT's beam-4 the margin is +3.85 chrF++.
3. **Is the RL gain additive? Partly redundant.** The gain of RL over the SFT shrinks from +7.56 (greedy) to +3.07 (beam-4) and +2.52 (MBR-16): 41% and 33% of the greedy gain remain (AfriCOMET: +0.057 -> +0.041 / +0.039, 71% / 68%). Both stay far above +1.0 (lower bounds +2.67, +2.26), so RL adds something that these decoders do not; the interactions exclude 0 (-4.48 [-5.18, -3.79] and -5.04 [-5.57, -4.42]), so the greedy gain overstates the RL's own contribution by about 4.5 to 5 chrF++ on these 20 languages, which is the finishing/looping repair that decoding also gives (finished 0.915 -> 1.0 and independent loop 0.147 -> 0.108 / 0.016 for the SFT with beam-4 / MBR). With the HF-rule beam the SFT is not repaired and the RL gain is unchanged (interaction -0.12 [-0.85, +0.55]). This is the same picture as the E-01 loop-guard control (the guard also removes about half of the greedy gain) on a different intervention.
4. **ESTIMATED beam gain of +5.0** over the 768-cap greedy (EXPERIMENTS_LEFT): measured +3.71 [+2.78, +4.47] for the SFT (the interval excludes 5.0) and -0.77 for the RL model.
5. Noise: no seed noise exists here; differences below 0.5 chrF++ are not interpreted (none of the verdicts rests on one).

## 4. Caveats and what was not done

* 20 languages x 200 sentences, one SFT and one RL checkpoint, vLLM bf16 greedy-family decoders (the engine parity gate of D6 is not met: absolute values can move by a few tenths of chrF++ with another engine; paired differences between decoders use the same engine).
* MBR is metric-matched (utility chrF++). Its AfriCOMET and spBLEU gains are smaller than its chrF++ gain on the RL model (+0.34 spBLEU), and for the RL model beam-4 (HF rule) is higher on spBLEU (18.47) and AfriCOMET (0.6227) than MBR (17.74, 0.6168).
* The primary beam definition was amended after the smoke test (Amendment 1): the unmodified vLLM beam loop (no early stop, running beams compete) produced 0 ended outputs of 120 on the SFT in the smoke test, so it was not run on the full set. The 256-token study (D1/D2/D5) used that loop with eos = `<eos>`; **its beam numbers are not comparable to the beam-4 here and the ledger rows built on them should be read as "vLLM exhaustive beam loop, eos <eos>"**. The old-eos diagnostic on the full set and the exhaustive loop at 768 tokens were not run.
* Not done: other beam widths / length penalties, language-specific decoding policy, the 54-language Tier-2 run (E-19), human evaluation.
